# Second Brain Acceptance Coordinator

## When to use

The owner asks whether a specialist agent is ready for consolidated acceptance, wants an
assessment of existing Phase B (or equivalent) evidence, or wants to know what's missing
before a specialist can be promoted.

## When NOT to use

- Debugging a specific failure trace (use **Second Brain Root Cause Coordinator**).
- Deciding to actually run a new live test — this Skill only classifies *existing*
  mirrored evidence and recommends the minimum additional test; it never runs one.
- Assessing shared-foundation components (Agent Coordinator, System Awareness,
  Preference Learning) — no equivalent checklist exists for those yet (see
  `docs/KNOWN_ISSUES.md` KI-043 / `command-center/PENDING_DECISIONS.yaml` PD-002); say so
  rather than forcing the specialist checklist onto them.

## Project context

This skill operates on the AI Second Brain project workspace at
`/home/jro/AI-Second-Brain-Development`. `command-center/` is a Cowork-owned
coordination/derived-state layer — never authoritative. `CLAUDE.md` at the project root
defines the full authority hierarchy; nothing this skill touches outranks it.

## Authoritative inputs

- `evidence-mirror/current/files/<agent-name>/**` — raw closeouts or sanitized receipts
  for the specialist in question.
- `docs/TESTING_AND_ACCEPTANCE.md` — the checklist's definition.
- `docs/KNOWN_ISSUES.md` — prior findings for this component.

## Evidence / freshness requirements

Confirm the read protocol (`evidence-mirror/current` resolves to
`status.json.current_snapshot_id`) before classifying. If the specialist's directory has
files marked `changed_review_required` or `unclassified` in the manifest, say so — those
files are not visible to this Skill by design and their absence should not be silently
treated as "no evidence exists."

## Allowed operations

- Read `evidence-mirror/current/**` (specialist-agent roots), `docs/TESTING_AND_ACCEPTANCE.md`,
  `docs/KNOWN_ISSUES.md`.
- Read multiple specialists' evidence in parallel when evaluating more than one.
- Produce a classification report (chat output or artifact) — no file writes required by
  this Skill's core function; it may optionally draft (not apply) a `command-center/DEVELOPMENT_BACKLOG.yaml`
  candidate item for the recommended next test.

## Prohibited operations

- No SSH, no `home` access, no production vault access, no submitting queue jobs of any
  kind — this Skill has no live-test capability at all.
- No writes to `docs/**`, `CLAUDE.md`, or `command-center/DEVELOPMENT_BACKLOG.yaml`
  directly (draft-only, per above).
- Do not describe or imply steps for executing a live production test — that crosses into
  Claude Code / Second Brain Claude Code Task Builder territory, gated on owner approval.

## Owner-approval boundaries

This Skill requires no approval to run (pure read + classify). Its output — "minimum
additional test needed" — is a recommendation only; actually running that test requires
the full **Second Brain Claude Code Task Builder** + owner-approval flow, entirely
separate from this Skill.

1. intended domain
2. retrieval relevance
3. grounding/provenance
4. permission behavior
5. queue/resource behavior
6. failure handling
7. phone/control surface

9. regression
10. no unauthorized external action

## Expected output structure

For each of the 10 criteria, classify exactly one of: **FULLY EVIDENCED**, **PARTIALLY
EVIDENCED**, **NOT EVIDENCED**, **NOT APPLICABLE** (state why), **FAILED / CONTRADICTORY
EVIDENCE**. Then: a plain-language conclusion first, then the minimum additional test
needed for any genuine gap (not a maximal retest of everything).

## Hard rules — violating any of these is a defect in this Skill's output, not a judgment call

- **Never treat NOT EVIDENCED as FAILED.** Absence of a test is not a failed test.
- **Never treat a mechanism-safety PASS as proof of output quality.** All safety flags
  `false` (as required) proves *permission behavior* passed — nothing about output
  quality. (Writing Agent's Phase B: safety flags all correct, core deliverable still a
  confirmed defect.)
- **Never treat grounded-but-irrelevant retrieval as successful retrieval relevance.**
  Citation coverage passing is a *grounding/provenance* result, not a *retrieval
  relevance* result. (Writing Agent test 2: Waze sources cited for a welcome-email draft —
  citation coverage passed, retrieval relevance clearly failed.)

+# spaces of indent (four makes it an indented code block), a run of at least
+# three backticks or tildes, and an optional info string.
+_FENCE_LINE_RE = re.compile(
+    r"^ {0,3}(?P<marker>`{3,}|~{3,})(?P<info>.*)$"
+)

+def fence_delimiter(
+    line: str,
+    open_marker,
+):
+    """Is this line a fence delimiter, and does it open or close?
+
+    Returns the marker that is now open ('```', '~~~~', ...), or None when
+    no fence is open, or False when the line is not a delimiter at all and
+    should be treated as ordinary content.
+
+    Treating every run of three backticks as a toggle was wrong in three
+    separate ways, all of which put text where it should not be:
+
+    - a closing fence may not carry an info string, so inside a fence the
+      line '```not-a-closer' is CONTENT. Toggling on it ended the fence
+      early, which both destroyed the real fenced content that followed and
+      let a heading inside the fence become the note's title.
+    - a fence may be four or more backticks, or tildes. Not recognising
+      those meant an author's literal fenced example lost its comments and
+      rules.
+    - a fence may be indented at most three spaces. Accepting deeper
+      indentation meant an indented code block was read as a fence, which
+      protected commented-out text and carried it into the evidence.
+
+    A closing fence must use the same character as its opener and be at
+    least as long.
+    """
+
+    match = _FENCE_LINE_RE.match(line)
+
+    if not match:
+        return False
+
+    marker = match.group("marker")
+    info = match.group("info")
+
+    if open_marker is None:
+        # A backtick fence's info string may not itself contain a backtick.
+        if (
+            marker[0] == "`"
+            and "`" in info
+        ):
+            return False
+
+        return marker
+
+    if (
+        marker[0] == open_marker[0]
+        and len(marker) >= len(open_marker)
+        and info.strip() == ""
+    ):
+        return None
+
+    return False

def _normalize_glob(raw, source_label):
    """
    Lexical normalization/validation of a vault-relative glob pattern.
    This never calls Path.resolve() on a pattern containing wildcards --
    resolving a wildcard string against the filesystem is meaningless.
    Canonical-vault-containment is checked separately, per actual
    candidate file path, in _path_within_vault().
    """

    if not isinstance(raw, str) or not raw.strip():
        raise RetrievalPolicyError(
            source_label
            + ": glob pattern must be a non-empty string."
        )

    stripped = raw.strip()

    if stripped.startswith("/") or stripped.startswith("\\"):
        raise RetrievalPolicyError(
            source_label
            + ": glob pattern must be vault-relative, not absolute: "
            + repr(raw)
        )

    if re.match(r"^[A-Za-z]:[\\/]", stripped):
        raise RetrievalPolicyError(
            source_label
            + ": glob pattern must be vault-relative, not absolute: "
            + repr(raw)
        )

    value = stripped.replace("\\", "/")

    while "//" in value:
        value = value.replace("//", "/")

    value = value.lstrip("/")

    if not value:
        raise RetrievalPolicyError(
            source_label
            + ": glob pattern must not be empty after normalization."
        )

    segments = value.split("/")

    if any(segment == ".." for segment in segments):
        raise RetrievalPolicyError(
            source_label
            + ": glob pattern must not contain '..' segments: "
            + repr(raw)
        )

    return value


def _glob_match_any(path, patterns):
    for pattern in patterns:
        if fnmatch.fnmatch(path, pattern):
            return True

    return False


def _path_within_vault(config, relative_path):
    """
    Verifies an actual candidate file's canonical resolved path is
    inside the canonical vault. Applied to real candidate paths coming
    out of the index, never to glob patterns (which may contain
    wildcards and cannot be meaningfully resolved).
    """

    try:
        vault = Path(
            config["vault_root"]
        ).resolve()

        candidate = (
            vault
            / relative_path
        ).resolve()

        candidate.relative_to(vault)

    except (ValueError, OSError, KeyError, TypeError):
        return False

    return True

   837	def fence_delimiter(
   838	    line: str,
   839	    open_marker,
   840	):
   841	    """Is this line a fence delimiter, and does it open or close?
   842	
   843	    Returns the marker that is now open ('```', '~~~~', ...), or None when
   844	    no fence is open, or False when the line is not a delimiter at all and
   845	    should be treated as ordinary content.
   846	
   847	    Treating every run of three backticks as a toggle was wrong in three
   848	    separate ways, all of which put text where it should not be:
   849	
   850	    - a closing fence may not carry an info string, so inside a fence the
   851	      line '```not-a-closer' is CONTENT. Toggling on it ended the fence
   852	      early, which both destroyed the real fenced content that followed and
   853	      let a heading inside the fence become the note's title.
   854	    - a fence may be four or more backticks, or tildes. Not recognising
   855	      those meant an author's literal fenced example lost its comments and
   856	      rules.
   857	    - a fence may be indented at most three spaces. Accepting deeper
   858	      indentation meant an indented code block was read as a fence, which
   859	      protected commented-out text and carried it into the evidence.
   860	
   861	    A closing fence must use the same character as its opener and be at
   862	    least as long.
   863	    """
   864	
   865	    match = _FENCE_LINE_RE.match(line)
   866	
   867	    if not match:
   868	        return False
   869	
   870	    marker = match.group("marker")
   871	    info = match.group("info")
   872	
   873	    if open_marker is None:
   874	        # A backtick fence's info string may not itself contain a backtick.
   875	        if (
   876	            marker[0] == "`"
   877	            and "`" in info
   878	        ):
   879	            return False
   880	
   881	        return marker
   882	
   883	    if (
   884	        marker[0] == open_marker[0]
   885	        and len(marker) >= len(open_marker)
   886	        and info.strip() == ""
   887	    ):
   888	        return None
   889	
   890	    return False

  1024	def classify_markup(
  1025	    lines: list[str],
  1026	    fm_end: int,
  1027	) -> list[dict]:
  1028	    """Classify every line of a note once, before anything is chunked.
  1029	
  1030	    Returns one dict per line, aligned with `lines`, carrying:
  1031	        number   1-based line number
  1032	        kind     'keep' or 'drop'
  1033	        text     the line's content after markup removal ('' when dropped)
  1034	        fenced   True if the line sits inside a fenced block
  1035	
  1036	    Every markup decision here is line-local, so no pattern CAN span lines,
  1037	    whatever it is written as. That is what closed the first three attempts
  1038	    at this defect, each of which let a marker pattern run past its own line
  1039	    and delete the content between two markers.
  1040	
  1041	    A comment may only remove text it actually encloses. An earlier version
  1042	    discovered that after the fact and handed the swallowed lines back. That
  1043	    restored their TEXT but not the STATE the wrong decision had produced:
  1044	    fence tracking had already run with those lines consumed, so a heading
  1045	    textually inside a fence could become the note's title and the fence
  1046	    delimiters reached the evidence.
  1047	
  1048	    So the decision is made before it is acted on. The pass runs, and if a
  1049	    comment opener turns out never to close, that opener is recorded as
  1050	    ordinary text and the whole pass is run again with it. Each restart
  1051	    settles one opener, so this terminates, and the classification that is
  1052	    finally returned was computed with the right answer from the first line
  1053	    - fence state included. There is nothing left to undo.
  1054	    """
  1055	
  1056	    literal_openers: set = set()
  1057	    classified: list[dict] = []
  1058	
  1059	    # Bounded, not merely convergent. Each restart settles one opener and a
  1060	    # note has at most len(lines) of them, so the bound is never reached while
  1061	    # this function is correct. It is written as a bound rather than a
  1062	    # progress check because a progress check only catches the shape of
  1063	    # non-progress it tests for: an earlier version guarded against the same
  1064	    # opener being re-reported, and a change that simply stopped recording
  1065	    # openers still span forever. Indexing a note must always finish, so the
  1066	    # loop cannot depend on the body being right.
  1067	    for _ in range(len(lines) + 1):
  1068	        classified, unterminated = _classify_once(
  1069	            lines,
  1070	            fm_end,
  1071	            literal_openers,
  1072	        )
  1073	
  1074	        if unterminated is None:
  1075	            break
  1076	
  1077	        literal_openers.add(unterminated)
  1078	
  1079	    return classified

   581
